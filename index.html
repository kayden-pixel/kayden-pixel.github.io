About me

I care more about the finished server than the tech buzzwords.

I build things because I run and manage real communities myself. That means I end up dealing with the boring-but-important parts too: permissions, broken plugin interactions, upgrades, world rules, build errors, staff tooling and player-facing polish.

My strongest day-to-day language is Node.js. That's what I reach for when I'm building Discord bots, APIs, real-time systems, automation or backend tooling. For Minecraft, I work in Java with Paper/Purpur. Python is mostly part of my AI stack: model integrations, voice tooling, automation and assistant systems.

On Minecraft work, I don't only look at one plugin at a time. I work across the whole setup: worlds, Multiverse, WorldGuard, LuckPerms, PlaceholderAPI, Vault, DiscordSRV, Geyser/Floodgate, scoreboards, MOTDs, moderation, protection, anti-cheat, economy, custom plugins and whatever glue is needed between them.

I'm especially comfortable fixing existing systems that are almost working but have weird version, permission, configuration or runtime problems. I use CFR when I need to inspect Java plugin behavior, compile against modern Paper APIs, and validate the final JAR instead of assuming a build is good because it compiled once.

Minecraft delivery

What I can handle on a client Minecraft setup.

If you want to sell or deliver prebuilt Minecraft server setups, this is the work I can take ownership of: the playable world structure, configuration, custom code, integrations and the testing before it is handed over.

World & lobby architecture

Create/import worlds, flat or custom lobbies, spawn positioning, gamemode/difficulty, time and weather rules, PvP/hunger behavior, portal settings, respawn behavior, Multiverse registration and WorldGuard protection.

Plugin stack configuration

Set up LuckPerms, PlaceholderAPI, Vault, WorldGuard/WorldEdit, Multiverse, DiscordSRV, Geyser/Floodgate, TAB/scoreboards, MOTDs, economy, homes, moderation, anti-cheat, powers and other gameplay plugins so they work together.

Custom plugin work

When an existing plugin cannot do the exact job, I can build Java/Paper features, extend an existing internal system, add GUIs, commands, listeners, persistence, integrations, diagnostics and admin controls.

Debugging & handoff

Test commands, permissions, world behavior, plugin compatibility, startup/runtime errors, Java version problems, config conflicts and player flows, then leave the setup organised enough that somebody else can maintain it.

Process

Build it like it has to survive players.

01

Define

Work out the game mode, server flow, required features, versions, plugin stack, and what needs custom code.

02

Build

Create the worlds, configs, permissions, integrations, plugin systems, and player-facing experience as one setup.

03

Validate

Check permissions, dependencies, runtime behavior, edge cases, compatibility, and the actual player path through the server.

04

Deliver

Package a clean setup with understandable structure so it can be deployed, maintained, and extended instead of becoming config chaos.
